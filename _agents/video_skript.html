0 · Intro

0:15 · README des Forks auf GitHub, kurz scrollen bis zum Architekturdiagramm

Hallo, wir sind Oskar Klöpfer, Carl Hirschberg, Can Kal und Daniel Brose, Gruppe kloepfer-brose-hirschberg-kal. Wir zeigen unsere Lösung für yourmuesli.at: Ein ESP32 mit DHT11 misst Temperatur und Luftfeuchte, sendet per MQTT an den Kurs-Broker, und ein Docker-Stack speichert die Daten aller Gruppen in SQLite und zeigt sie in Grafana und auf einer eigenen Website.

1 · Gerät startet

0:30 · Kurz Foto/Kamera der Verkabelung, dann serielle Konsole
Zeigen
cd src/esp32_firmware
pio device monitor        # danach EN/RESET-Taste am ESP32 drücken
  • DHT11 an 3V3, GND und GPIO 4
  • Ausgabe: WiFi connected. IP: …, Time synced: …Z, connected!, erste Published …-Zeilen
Sagen

Der DHT11 hängt an 3,3 Volt, Masse und GPIO 4. WLAN- und Broker-Zugangsdaten kommen aus einer .env-Datei, die beim Kompilieren eingebunden wird – sie ist nicht im Repository.

Nach dem Reset verbindet sich der ESP32 mit dem WLAN, hier sieht man die IP-Adresse, holt die Uhrzeit per NTP in UTC und verbindet sich mit dem Broker. Danach sendet er alle fünf Sekunden Temperatur und Luftfeuchte.

2 · MQTT: Messwerte, Status, Last Will

0:40 · MQTT Explorer · Schnitt während der ~20 s Wartezeit
Zeigen
  1. …/sensor/temperature/state anklicken: Payload mit timestamp, value, unit, sensor_id
  2. …/sensor/humidity/state kurz zeigen
  3. …/status: {"status":"ok",…}, retained
  4. USB-Kabel ziehen → Schnitt → {"status":"offline",…} erscheint
  5. Wieder einstecken → Status springt auf ok (Konsole ggf. neu öffnen)
Sagen

Im MQTT Explorer sieht man unsere Topics nach der Konvention iiot/group/Gruppenname/sensor/Messgröße/state. Jede Nachricht ist JSON mit Zeitstempel in UTC, Wert, Einheit und Sensor-ID.

Auf dem Status-Topic steht retained „ok“. Beim Verbinden hinterlegen wir beim Broker einen Last Will. Wenn wir das Gerät jetzt abstecken …

… meldet der Broker nach Ablauf des Keep-Alive automatisch „offline“. Liefert der Sensor ungültige Werte, senden wir „error“. Nach dem Einstecken steht der Status wieder auf „ok“.

3 · HTTP-API und Testfälle

0:55 · Terminal links, MQTT Explorer rechts · Testlauf (~45 s) schneiden
Zeigen
curl http://192.168.68.62/status
curl http://192.168.68.62/config
curl -X POST http://192.168.68.62/config -H 'Content-Type: application/json' \
     -d '{"reading_interval_seconds": 10}'
  • Im MQTT Explorer: Nachrichten kommen jetzt im 10-s-Takt (Zeitstempel vergleichen)
  • Optional: Fehlerfall curl -X POST … -d '{"reading_interval_seconds": 1}' → 400
DEVICE_URL=http://192.168.68.62 pdm run pytest -v
  • Anfang zeigen, schneiden, Ende 35 passed zeigen
Sagen

Im lokalen Netz bietet der ESP32 eine HTTP-API nach unserer OpenAPI-Spezifikation. GET /status liefert Uptime, WLAN- und MQTT-Verbindung und den letzten Messwert, GET /config die aktuelle Konfiguration.

Mit POST setzen wir das Sendeintervall auf zehn Sekunden. Der Wert wird im Flash gespeichert, und im MQTT Explorer sieht man, dass die Nachrichten jetzt alle zehn Sekunden kommen. Ungültige Werte, kaputtes JSON, falsche Pfade oder Methoden beantwortet das Gerät mit 400, 404 oder 405.

Unsere Testfälle laufen mit pytest gegen das echte Gerät: gezielte Tests für alle Endpunkte und Fehlerfälle und zusätzlich Schemathesis, das aus der OpenAPI-Spezifikation automatisch Anfragen erzeugt und die Antworten gegen das Schema prüft. Alle 35 Tests sind grün; danach wird das ursprüngliche Intervall wiederhergestellt.

4 · Container starten

0:20 · Terminal im Hauptverzeichnis
Zeigen
docker compose up -d
docker compose ps
  • Vier Dienste collector, api, grafana, website mit healthy
Sagen

Der ganze Stack startet aus dem Repository mit docker compose up. Nach einem frischen Clone muss man nur die .env.example kopieren und das Broker- und ein Grafana-Passwort eintragen. Es laufen vier Container: der Collector, der alle Gruppen vom Broker abonniert und in SQLite speichert, Grafana, eine kleine Lese-API und unsere Angular-Website.

Im Grafana-Dashboard sehen wir Temperatur und Luftfeuchte live, das Dashboard aktualisiert sich alle zehn Sekunden. Wenn ich den Sensor anfasse, steigt die Temperatur. Dieselben Daten zeigt auch unsere Website, mit Filtern für Zeitraum, Gruppe und Sensor.

6 · Bewertungsstufen

0:50 · Terminal + Grafana
a) Datenbank – befriedigend
docker compose exec collector python -c "import sqlite3; d=sqlite3.connect('/data/measurements.sqlite'); [print(r) for r in d.execute('SELECT group_name, sensor_id, metric, value, unit, datetime(time, \'unixepoch\') FROM readings ORDER BY id DESC LIMIT 5')]"

Die Daten liegen in einer SQLite-Datenbank in einem Docker-Volume: Rohnachrichten, Messwerte und eine Gerätetabelle. Hier die letzten Messwerte.

b) Neuer Sensor ohne Konfiguration – gut
mosquitto_pub -h 158.180.44.197 -u bobm -P "$MQTT_PASSWORD" \
  -t 'iiot/group/test-kloepfer/sensor/temperature/state' \
  -m '{"timestamp":"2026-11-27T12:00:00Z","value":23.5,"unit":"°C","sensor_id":"demo"}'
  • Passwort nicht tippen/zeigen: vorher export MQTT_PASSWORD=… außerhalb der Aufnahme, oder im MQTT Explorer unter „Publish“ senden. Zeitstempel auf die aktuelle UTC-Zeit setzen.
  • Grafana neu laden → Gruppe test-kloepfer erscheint in Gruppenfilter und Geräteübersicht

Der Collector abonniert iiot/group/#, neue Sensoren werden also ohne Konfiguration aufgenommen. Wir senden eine Testnachricht für eine neue Gruppe, und sie erscheint sofort im Dashboard. Andere Gruppen sieht man hier ja ohnehin schon.

c) Geräteübersicht – sehr gut
  • Panels „Anzahl Sensoren“ und „Geräteübersicht“ oben im Dashboard

Für die Übersicht wertet der Collector zusätzlich die Status-Topics aller Gruppen aus. Oben sehen wir die Anzahl bekannter und aktiver Sensoren und in der Tabelle für jede Gruppe den Status – ok grün, error und offline rot –, wann die letzte Statusmeldung und der letzte Messwert kamen. Unser Gerät von vorhin war zwischenzeitlich offline und ist jetzt wieder ok.

d) Kennzahlen – Bonus
  • Tabelle „Alle Messwerte im Zeitraum“: Minimum, Maximum, Mittelwert, Anzahl

Als Bonus berechnet das Dashboard für den gewählten Zeitraum Minimum, Maximum und Mittelwert pro Sensor.
